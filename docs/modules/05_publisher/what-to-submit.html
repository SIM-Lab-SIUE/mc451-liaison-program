What to Submit: Your Final Deliverables

By Phase V, you’ve done serious research. Now it’s time to share it. The final submission for this course has two parts: a PDF report and a live GitHub Pages website. This page explains exactly what each one is, what goes in it, and how to make sure you haven’t missed anything.

The Two Final Outputs

PDF Report GitHub Pages Website
What it is A formatted research document A public website with your portfolio
Rendered from Your .qmd file with format: pdf Your .qmd file(s) with format: html
Audience Academic (instructor, peers) Public (potential employers, classmates)
Submitted how Uploaded to Blackboard or emailed URL submitted — the site itself is the submission
Contains Full report with citations, tables, figures Same content, plus your research process and vault highlights

Both documents are produced from the same Quarto files — you just render them with different format settings.

Rendering to PDF

In your .qmd file’s header, set:

---
title: "Your Report Title"
author: "Your Name"
date: today
format: pdf
---

Then click Render in RStudio. The PDF will appear in your project folder and open automatically.

TipPDF Rendering Requires a LaTeX Installation

If you see an error like "xelatex not found" when rendering to PDF, you need to install TinyTeX. Run this once in the RStudio Console:

install.packages("tinytex")
tinytex::install_tinytex()

This takes about 5 minutes. After it completes, restart RStudio and try rendering again.

A finished portfolio typically has a simple navigation bar at the top, a clear headline for the project, and 2–3 paragraphs describing what you studied and what you found — written for a general audience, not an academic one.

Publishing to GitHub Pages

  1. Render your Quarto site (it outputs to the docs/ folder)
  2. Commit and push all files to GitHub
  3. In your GitHub repository, go to Settings → Pages
  4. Set the source to “Deploy from a branch”, branch: main, folder: /docs
  5. Click Save. Your site will be live within a few minutes.

After publishing, test every link on your site in a browser (not just in RStudio’s preview).

Common Last-Minute Problems

“My PDF renders locally but not on GitHub” GitHub Pages only hosts HTML — the PDF is a separate file you produce locally and then push to the repository. Make sure the PDF is committed to your docs/ folder.

“My charts look fine in RStudio but are missing in the PDF” Check that your code chunks that produce plots use echo: false if you don’t want the code shown, and make sure the chunk is not set to eval: false. Also ensure ggplot2 is loaded.

“My GitHub Pages site is showing a 404 error” Check that (1) the /docs folder exists and contains an index.html, and (2) GitHub Pages is configured to serve from /docs on the main branch. It can take up to 10 minutes for changes to go live.

“I don’t know if I need the full PDF in the website” You should have both. The PDF is the academic deliverable. The website is the portfolio. Link to your PDF from the website so visitors can download it.
